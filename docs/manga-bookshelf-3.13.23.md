# v3.13.23 マンガ本棚

基準: main `045506a` / v3.13.22。

## 画面とルーティング

起動時の確定した `contentFilter.type === 'manga'` を `startSelectedView` が
`viewMode = 'bookshelf'` にルーティングする。他の種別は従来のフィード。
フィルタと表示モードは独立状態。年齢条件を変えても本棚のソース/検索語は維持する。

本棚の取得元はブックマーク、おすすめ・人気、検索の3タブ。
「おすすめ・人気」タブは初版では日間マンガランキングのみを使用する。
`bookshelfProviders` で取得経路を分け、後続の推薦ソースを追加できる。
人気順と好み順を混ぜたスコアは作らない。

シリーズは1タイル、単発は1作品1タイル。未検証候補は無画像・無タイトルの
操作不可プレースホルダにし、種別・年齢・シリーズ所属を確認後に表示する。
タイルの順位は所属候補の最小順位（最上位作品）だけ。話数・平均・味付け加点はない。
検索は既存検索プール、候補準備、`searchRankCandidates` の結果をそのまま集約する。
検索の tier/tasteScore/同点比較は変更しない。

シリーズタイルは明示的なシリーズ情報を `seriesShowList(info)` に渡す。
選択した話は `seriesOpenEpisode(item, source)` と既存の専用読者で読む。
検索に一致しない話もシリーズ一覧から読めるが、本棚の候補集合には加えない。
単発は既存フィードに選択作品1件を置いて読む（推薦の自動差し込み/追加取得は停止）。
読書中の「閉じる」や「本棚へ」、一覧シートの閉じるは本棚のスクロール位置へ戻る。
本棚そのものを閉じるときは従来の確認フローと自動再起動抑止を使用する。

## 段階的取得と集約

- ブックマーク: 100件/ページ、1操作で最大3ページ。マンガ候補が12件以上見つかれば
  その操作の一覧取得を止める。公開分の後は本人の非公開分も取得する。
  一覧の取得・判定を履歴学習用データに流し込まない。
- ブックマークにはシリーズ情報がないため、可視範囲とその近傍の候補から詳細を取得し、
  `seriesNavData`、または自身の `userIllusts[id].seriesId` で所属を補完する。
  本棚の詳細/表紙取得は同時3件、1リクエスト8秒、詳細キャッシュ150作品、
  シリーズ表紙メタデータ30件。読み込み失敗は明示的なタイル再試行のみ。
- 人気: `ranking.php?mode=daily&content=manga&p=N&format=json`。明示的な追加取得ごとに
  次ページへ進み、最大10ページ（500件）。`illust_series` も所属補完に利用する。
- 検索: 既存の1バッチ最大3ページの共有取得を再利用。全取得済み候補の元の検索順位で
  集約し直す。本棚上限をまたぐバッチも、上位500候補を採用してから集約する。
- 各本棚は最大500候補。追加の取得は「続きを取得」の手動操作。ブックマーク7,263件を
  一括詳細照会しない。除外された作品を否定的な学習には使わない。

ブックマークの話数は **現在条件に合う、取得済み分の確認数**。
「ブックマークN話（取得済み分）／全M話」と表示する。未取得のブックマークを
未保存と断定しない。全件取得前にアカウント全体の正確なNを保証するものではない。
MはシリーズAPIが返す全話数（現在フィルタに合わない話も含む）。

## 表紙と年齢フィルタ

第1話のIDは `/ajax/series/{id}?p=1` の `illustSeries[].firstIllustId` から取得し、
最終ページの `thumbnails.illust[]` を **IDで照合** する。配列位置は使用しない。
第1話が取得不能・メタデータ不明・年齢条件外なら、別話を表紙にせず無画像で表示する。
メタデータキャッシュはフィルタ非依存で保持し、利用時に現在条件を再検証する。

ランキングには xRestrict がないため、可視候補の作品詳細で種別と年齢を検証する。
確認完了前にランキングサムネイルを表示しない。不明値は遮断し、R-18のみは
xRestrict=1だけを通す。シリーズ一覧・専用読者の既存 fail-closed 判定も維持する。
指定された通常の日間ランキングにはR-18作品がない場合がある。
R-18専用ランキングへの自動切り替え・条件緩和は行わず、0件時は説明を表示する。
pixivアカウント側の閲覧設定を変更・回避しない。

## 右から左の読書

本棚の単発マンガは既存の複数ページビューアをRTLにし、負のscrollLeftを考慮する。
専用シリーズ読者は左矢印で次ページ、右矢印で前ページ。操作ボタンもRTL配置。
右向きスワイプ（左側の次ページを引き出す操作）、上向きスワイプ、縦ホイール前進に対応。
最終ページからさらに前進すると、一覧へ戻らず次話の先頭へ進む。
次話にも年齢/種別判定を適用し、条件外の場合は画像を出さず理由を表示する。
読書中の重複リクエストはbusyフラグ、ホイールの連続発火は500msの間隔で抑制する。
通常フィードの従来のページ送り方向は変更しない。

## 検証と範囲

```sh
node --check pixiv-tate-scroll.user.js
git diff --check
node tests/bookshelf.cjs
node tests/content-filter.cjs
```

PlaywrightとChromiumが必要（`CHROMIUM_PATH` で指定可能）。
本棚テストはuserscript全体をChromiumで実行し、APIを模した応答で以下を確認する。

- マンガ起動、3ソース、まばらなブックマークの段階取得、同時詳細取得3件以下
- シリーズ集約、第1話表紙の最終ページ/ID照合、取得済み話数と総話数
- 最上位候補の順位を使う集約と、平均順位で逆転するケースの防止
- 単発RTL、シリーズ情報の引数渡し、シート/読者を閉じた後の位置復帰
- 左矢印・スワイプ・ホイール、最終ページから次話、次話の年齢遮断
- ランキング年齢検証、検索ランキング関数の基準版との一致、候補/読書資格の分離
- ソース切り替え中の遅延応答破棄、0件・失敗時の無限ループ防止、明示的再試行
- フィルタ変更時のキャッシュ再検証、非マンガへの再ルーティング、取得で学習しないこと

既存のフィルタテストは本棚ルーティングだけをテスト用に無効化し、従来フィード内の
全経路フィルタを引き続き検証する。本棚の実ルーティングは本棚テストで検証する。
モバイル390px幅の画面も目視確認した。ログイン済みの実アカウントに対する
ライブAPI検証は未実施。読書進捗・既読表示・本棚の永続化・差分更新は実装しない。
