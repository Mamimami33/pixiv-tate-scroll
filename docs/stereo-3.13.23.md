# v3.13.23 裸眼立体視（平行法・交差法）

1枚絵からAIで奥行きを推定し、左目用と右目用の絵を作って横に並べる。メガネなしで、
目の焦点をずらして2枚を重ねると立体に見える。ユーザースクリプト版でもSafari拡張機能版でも動く。

## 動き

- 静止画とマンガ（うごイラ以外）の右上に「立体視」ボタンが出る。押すたびに
  OFF → 平行法 → 交差法 → OFF と切り替わり、設定は `PTS_STEREO_V1` に保存する。初期値はOFF。
- 平行法は左目用の絵を左に、交差法は右に置く。上の2つの白い点は目印で、
  点が3つに見えるように目の力を抜く（交差法は寄り目にする）と、真ん中の絵が立体に見える。
- ONのあいだは、表示中の作品・ページが変わるたびに作り直す。作成中は「準備中…」、
  AIの初回読み込み中は「AI読込中…」と出る。平行法と交差法の切り替えは作り直さない。
- 使えない場合は「立体視 不可」と出て、元の表示のままになる。
  診断の「立体視:」の行に、実行場所、直近の所要時間、理由を出す。

## 画像の読み取りについて（重要）

- 立体視は画像の画素を読む必要がある。pixivの画像は別の配信サーバーにあり、
  通常の表示用の読み込みでは画素を読めないので、許可つき(CORS)の読み込みを
  **1作品（1ページ）につき1回だけ**行う。これは表示用とは別の、追加の画像取得になる。
- 配信サーバーが許可しなかった場合は、そのページを開いている間は二度と試さない。
  制限を回避する手段（別経路での取得、外部の中継サーバーなど）は使わない。
  これは `feat/pixiv-enhance-only-20261111` 系で決めた方針（403後は再試行しない）に合わせている。
- 過去の実機報告では、Safari Userscriptsからの画像の取り直しが403になっている。
  今回の読み込み方が通るかどうかは実機で試すまで分からず、通らなければこの機能は使えない。

## 仕組み

- 奥行き推定は Depth Anything V2 Small（Apache-2.0、int8版、約27MB。npm
  `@richardmcquiston01/ai-tools` 0.5.1 に同梱のONNX）。取得元と保存の仕組みはコマ補間と同じで、
  ユーザースクリプト版は初めてONにしたときに配信サーバーから取得し、SHA-256を確認して端末に保存する。
- 計算はCPU(WASM)で1〜数秒かかるので、別スレッド(Worker)で動かして画面操作を止めない。
  Workerを作れない環境では同じ処理をページ内で動かす（その間は操作が止まる）。
- 奥行き推定は長辺392pxに縮めて行う。片目ぶんの絵は幅640pxまで。
- 左右の絵は、各画素を「奥行き × 幅の2.2%」まで横にずらして作る。重なった所は手前を残し、
  手前の物がどいて現れる隙間は奥側の絵を折り返して埋める。画面の基準は奥行きの平均。
- 画像を外部に送ることはない。計算は端末の中だけで行う。

## 確認できたこと（Chromiumで検証。`tests/stereo.cjs`）

- 左右の絵を作る計算: 奥行きが分かっている合成データで、手前の帯が指定どおり左右にずれ、
  奥は動かず、隙間が残らないこと。
- 空と床の手前に赤い玉を描いた絵で、平行法では左の絵の玉が右寄りに、交差法ではその逆になること
  （AIが玉を手前と推定し、正しい向きにずれている）。OFFで元の表示に戻ること。
- ONにするまで配信サーバーへ通信せず、画像も読み直さないこと。画素の読み込みは1作品1回。
- 画素の読み込みに403が返る場合は「不可」で止まり、取り直さず、AIも取得しないこと。
- 拡張機能版は同梱のファイルだけで動くこと。
