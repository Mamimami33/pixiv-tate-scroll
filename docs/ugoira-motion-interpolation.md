# うごイラの高画質化・動き補間（v3.13.25 試作）

2026-11-11 / 基点: `main 045506ab` → 低負荷ブランチ → ローカル補間ブランチ → 本ブランチ。

## 目的と現在の到達点

**完成目標**は「静止画に対する学習済みモデルの超解像」と「うごイラに対する自然な中間フレーム生成」。現段階では、後者について **WebGL2による非AIの局所動き推定補間** を試作した。**RIFE・Real-ESRGAN・Anime4K CNNはまだ組み込んでいない**。単純な2×Canvas拡大をAI超解像と呼ばない。

## 現在利用できる試作

- **動き補間：OFF/ON**: ZIPを展開したローカル`blob:`画像を2枚デコードし、160px以内の解析画像から12pxブロック・±4pxの局所移動を推定。WebGL2で前後の元画像を移動ベクトルで補正し、表示時刻の割合に応じて中間画像を描画する。ブラウザの`requestAnimationFrame`上で動くため、端末の画面更新頻度とGPU性能が上限。
- **うご原寸優先：OFF/ON**: 次のうごイラから、`originalSrc`があれば最初からフルサイズZIPを選ぶ。既存の「小ZIP→大ZIPへの高画質差し替え」よりリクエスト数を減らし得るが、短時間閲覧ではダウンロード量が増えることもある。
- **補間2×：OFF/ON**: 前ブランチ由来の端末内Canvas拡大補間。非AIで、元画像の解像度が既に十分なら処理しない。

これらはすべてデフォルトOFF。現在のスクリプトはSafariへの適合試験前のため、**mainに統合していない**。

## 負荷・メモリ・プライバシー

- 動き補間は既に取得したZIP内画像だけを利用し、pixivへのGETは追加しない。
- `frame`解析用の画像は最大160px角。2枚の元画像が合計で過大にならないよう各画像250万画素を上限にする。
- 出力Canvas最大125万画素。同時に1作品だけを補間し、離脱時はGPUテクスチャとCanvasを解放。
- 25～300msのフレーム間隔に限定。大きな場面切替（平均輝度差が高いもの）は補間を中止して原フレームに戻す。
- うごイラの元フレームが`blob:`でない場合、動き推定のためのピクセル読み取りは行わない。
- モデル・フレーム・計算結果を外部AIへ送信しない。外部コードを動的に取得しない。
- WebGL2非対応・失敗時は元のフレーム表示を維持。
- 中間フレームは動きの推定に基づくが、**RIFE等のニューラルモデルではない**ため、複雑な変形・激しい移動では残像、歪み、誤った輪郭が出得る。

## 今後の真のAI超解像の設計

1. **WebGPU能力検査**: `navigator.gpu` とGPUアダプタ取得を確認し、失敗時は処理を無効化。Apple WebKit はSafari 26からWebGPUを搭載したが、利用予定の推論ライブラリのSafari実対応は別途検証が必要。
2. **モデル選定**: イラスト向けAnime4K CNNx2系と、静止画向けReal-ESRGAN系を比較。ライセンス・重量・モデル供給元を確認。配信時に第三者から任意JavaScriptを読み込む設計を避ける。モデルは可能なら同梱し、外部モデル取得する場合は明示操作・固定ハッシュ・安全な配信元を要求する。
3. **処理の優先度**: 元サイズ画像をまず表示し、低解像度の場合だけGPU超解像を非同期で適用。スクロール離脱で中断して元画像に戻す。1作品1処理、最大画素数・時間・メモリ予算とリトライ抑制を設ける。
4. **AIフレーム補間**: RIFEなどの学習済みモデルは別エンジンとして後付けし、低解像度・短尺のうごイラで実機測定してから採否を決める。フレーム0・連番の整合性、原本のフレーム遅延を守る。重い場合は今回の動き推定型か原画再生へフォールバック。
5. **画質評価**: 同じフレームの原本と処理結果をA/B比較。線・文字・色・細部の破綻を人が評価。実機でWebGL/WebGPU context lost・発熱・バッテリー・Safariタブのリロード・FPSと通信回数を計測する。
