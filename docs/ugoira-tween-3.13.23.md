# v3.13.23 うごイラのAIコマ補間

うごイラは「静止画の束＋1枚ごとの表示時間」でできている。前後のコマから中間のコマをAIで作り、
コマ数を2倍にして再生する。ユーザースクリプト版でもSafari拡張機能版でも動く。

## 動き

- うごイラの右上に「コマ補間」ボタンが出る。押すとON/OFFが切り替わり、
  設定は `PTS_UGOIRA_TWEEN_V1` に保存する。
- 初期値はユーザースクリプト版がOFF、拡張機能版がON。ユーザースクリプト版は初めてONにしたときに
  AIのファイル（合計約50MB）を取得するので、ONにするまで配信サーバーへは一切通信しない。
  モデル（約23MB）は端末に保存し、2回目以降は取り直さない。
- 対象は表示中のうごイラだけ。再生が始まったらすぐ中間コマを作り始め、高画質ZIPの取得は待たない。
  途中で高画質版に差し替わっても、作成済みの中間コマは捨てずに使い続ける。
- 作成中も再生は止めず、できた中間コマから順に（約1.2秒おきに）再生へ反映する。
  ボタンには「AI読込中…」「準備中 12/40」と進み具合を出し、全部できたら青の「コマ補間 ON」になる。
  作成済みの中間コマは作品が片付けられるまで残るので、ONに戻すとすぐ使われる。
- ONのときは、うごイラの作品情報を取得した時点（表示する前）でAIの読み込みを始めておく。
- 元コマの表示時間を半分ずつに分けて後半を中間コマに割り当てる。1周の長さは変わらないので、
  シークバー、ループ回数の学習、自動送りはそのまま。
- 補間しないコマ間: 表示時間が34ms未満（既に約30fps以上）、2コマがほぼ同じ、
  2コマの差が大きい（場面転換とみなす。最後→最初の継ぎ目も同じ判定）。
- 補間しない作品: 240コマ超、ZIPを展開できず個別画像で再生しているもの。「コマ補間 対象外」と出る。
- 使えない場合は「コマ補間 不可」と出る。ボタンを押し直すと読み込みからやり直す。
  診断の「コマ補間:」の行に、取得元、実行方式、WebGPUの有無、直近1枚の所要時間、エラー内容を出す。

## 仕組み

- AIモデルは RIFE 4.25（npm `@bvdmitri/webtween` 0.2.1 に同梱のONNX、MIT）。
  実行は `onnxruntime-web` 1.30.0 のWebGPU。どちらもバージョンを固定している。
- ユーザースクリプト版の取得元は jsDelivr、失敗したら unpkg。モデルはSHA-256を確認してから使う。
  拡張機能版は同梱のファイルを使い、外部には通信しない（`safari-extension/bridge.js` が場所を伝える）。
- 計算は端末の中だけで行い、画像を外部に送ることはない。配信サーバーには、
  ファイルを取得したという事実（IPアドレスなど通常のアクセス情報）だけが伝わる。
- WebGPUが使えない端末では動かさない。CPUで実行すると1枚に数秒かかり、その間は画面操作も
  止まるため。検証用に `PTS_UGOIRA_TWEEN_BACKEND` を `wasm` にするとCPU実行を強制できる。
- 補間の計算は長辺640pxまでに縮めて行い、中間コマはその大きさのまま持つ。
  再生用のcanvasは一番大きいコマに合わせ、小さい中間コマは引き伸ばして描く。

## 確認できたこと（Chromiumで検証。`tests/ugoira-tween.cjs`）

- 6コマのうごイラで、再生中の画面に映る位置が6か所から11か所に増え、中間コマでは
  被写体が前後のコマの中間位置に描かれる（残像の重ね合わせではない）。OFFで6か所に戻る。
- ユーザースクリプト版: ONにするまで配信サーバーへ通信しない。1つ目の取得元でモデルが
  取れないと2つ目に切り替わる。再読み込み後は保存済みのモデルを使う。
- 拡張機能版: 同梱のファイルだけで動き、配信サーバーへ通信しない。
- 小さいZIPで補間を始めた後に高画質ZIPへ差し替わっても、完了前から中間コマが混ざり始め、
  最後まで同じ結果になる。
- 検証はCPU実行で行った。このテスト環境で256pxが約0.4秒/枚、640pxが約2秒/枚。

## 未確認

- 配信サーバーから実際に取得できるか。この開発環境からは jsDelivr / unpkg に接続できず、
  テストでは同じファイルで代用した。特に約23MBのモデルと約28MBの実行ライブラリが
  サイズ制限にかからないかは実際に試すまで分からない。
- pixivのページの設定(CSP)が、外部のスクリプトやWebAssemblyの読み込みを止めないか。
  Userscriptsアプリの実行環境で `import()` が使えるかも含め、止められると「コマ補間 不可」になる。
- iPhoneでの速度とメモリ。WebGPUが使えるのはiOS 26以降のSafari。
  長時間の閲覧でSafariがページを再読み込みすることがありうる。
- 見た目。中間コマは640pxで計算して拡大するので、高画質の元コマより少し甘い。
  交互に出たときにちらついて見えないかは実機で要確認（上限は `UGOIRA_TWEEN_MAX_SIDE`）。
