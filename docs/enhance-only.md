# pixiv 画質向上・フレーム補間専用（v4.0.0-alpha.1）

2026-11-11 / **実験ブランチ**: `feat/pixiv-enhance-only-20261111`. 基点: 統合済みmain `045506ab`。mainにはマージしていない。

## 目的

既存の大規模「pixiv縦スクロール」から、ユーザーの依頼で**縦スクロール・関連推薦・フィード生成・検索・ブックマーク・診断・閲覧履歴・自動巡回機能を削除**し、次の2つに専念する。

- **静止画AI超解像:** 学習済みAnime4K v3.2 CNN x2 (S)の畳み込み4パス＋depth-to-spaceによる2倍GPU画像生成。単純な画素補間ではない。最大200万入力画素・800万出力画素、512pxコア＋12px余白で分割処理し、一度にGPUへ上げる領域を制限する。合成画像では実WebGL2処理までテスト済み。
- **うごイラフレーム補間:** ZIP内の隣り合うフレームのローカル領域の移動量を推定し、GPUで中間フレームを合成。ブラウザの画面更新に合わせて時刻を補間する。場面切替が大きいときは原画再生を優先。**AI RIFEではない**。実機での60fps保証はしていない。

機能を実行するための「今の作品を読み込む」「画像を選ぶ」「ZIPを選ぶ」、原画比較、再生/停止だけを残す。単一ユーザースクリプト `pixiv-tate-scroll.user.js` を置き換える設計。旧スクリプトは停止すること。

## pixivへの負荷

- 作品ページを開くだけでは追加のpixiv APIリクエストを送信しない。
- 「今の作品を読み込む」を押したときだけ、作品のJSONを取得する。うごイラではフレームJSONも取得し、元サイズZIP1つのみ取得する。自動リトライ・巡回はなし。
- Remote読み込みは操作ごとに最短5秒のクールダウン。HTTP 429後はページを開いている間のネットワーク取得を停止する。
- ファイルからのAI超解像と動き補間ではpixiv APIへアクセスしない。
- pixiv CDN側のCORSが許可しない場合は、画像やZIPを保存し、ファイルピッカーで読み込む。**CORS迂回や外部画像プロキシは利用しない。** 既に取得済みのフレームを処理し、ユーザーの画像を第三者に送信しない。
- pixiv側の実際の負荷や利用規約の適合性は未検証。数値的に「絶対安全」とは主張しない。

## セキュリティ・メモリ

- ZIP総容量64MiB、展開最大128MiB、フレーム数2〜120、各展開済みフレーム最大8MiB。
- ZIP展開にサイズ上限付きUint8Arrayを使用。ZIPヘッダー範囲・圧縮方式・展開後サイズを検証する。
- AIモデルはソースに同梱する。推論モデル・JavaScriptの動的CDN取得なし。
- Anime4Kの元配布MITライセンス全文は単一ユーザースクリプトおよび `docs/Anime4K-LICENSE.txt` に同梱する。
- 結果の比較表示は元画像へ戻せる。WebGL2非対応・画像ロード失敗時の安全側の挙動を優先する。
- ページ閉じ、画面遷移、ファイル差し替えの際に既存のblob URL・Canvas・WebGLを解放する。重いGPU処理はタイルごとに中断判定を入れる。
- **Safari実機のRAM/温度、GPUフレームレート、長時間動作は未確認。** 実機のメモリ安全を保証するものではない。

## 操作

1. Safari Userscriptsに試験版を設定し、旧縦スクロール版を無効にする。
2. pixiv作品の個別ページで「画質・コマ補間」を開く。
3. 作品を明示的に読み込む。CORSエラーなら端末保存した画像かZIPを選ぶ。
4. 静止画は「AI超解像2×」→「元画像を見る」でA/B比較。
5. うごイラは「動き補間: OFF/ON」。ZIP単体で開く場合に正式フレーム遅延情報がないと、100ms/枚として再生する。先にその作品のpixivメタデータを取得済みなら、ZIP内のファイル名と照合して本来の遅延を使う。

## 現在の検証

自動CI:
- 構文チェック
- Playwright/Chromiumで64×64の合成画像を**本物の学習済みCNN**に通し、128×128出力を検証
- **810×810→1620×1620**のタイル分割GPUテストと境界の不連続チェック
- ZIP保存形式・DEFLATE両方をデコードし、WebGLフレーム補間Canvasを実際に生成
- ZIPファイル処理では追加のpixiv通信ゼロ、任意のリモート取得では作品JSON×1、フレームJSON×1、ZIP×1
- ページ開いただけでは追加API呼出ゼロ

未確認:
- iPhone Safari実機での性能・GPUレンダリング・温度・メモリ・長時間連続再生
- 実際のpixiv作品での画質優劣の比較、CORS動作
- 真のニューラルAIフレーム補間（RIFEなど）。将来の研究項目であり、今回の動きベクトル補間をRIFEだと説明しない

## 保守上の原則

- 開発基準は常にGitHub最新mainと、対象ブランチの実コード。古いチャット上のパッチを統合済みとみなさない。
- main/公開版への統合は、Safari実機検証と利用者の明示的判断を経て行う。
- シンプルさを守る。これ以上おすすめ・検索・スクロール機能は戻さず、品質と安全性の改善に集中する。
